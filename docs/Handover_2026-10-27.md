The code is SlideMage `develop` at `4d402de` (2026-10-27). The plugin's copy differs only where step 1
separated it:

- `course_schedule` no longer finds SlideMage's cache folder itself; `use_cache_folder()` sets it, and without
  one nothing is kept and no course is soon.
- `admin_slides.plan_slides()` returns `(id_suffix, frame)`; the slide header and `\setSlideVersion{1-0-0}` are
  added in `bridge/insert.build_slide_source()`, since they are SlideMage's file format.
- `course_link` is `deck_scan.parse_course_url` and `deck_editor.normalize_course_url`/`course_url_text`,
  copied with the same behaviour.

## Things found on the way

- **No plugin code in SlideMage yet.** No branch of `stpalan/SlideMage` or the fork has a plugin host,
  `plugin_api`, `docs/PLUGINS_PLAN.md` or the handovers. The plugin side that exists: the template,
  `stpalan/slidemage-plugin-hello` (a catalogue test fixture; its `activate()` registers nothing), and the
  catalogue in `stpalan/slidemage-website` (conventions in `docs/plugins/submit.md`, `registry/plugins.toml`,
  SHA-256 pins, `tools/build_catalogue.py`).
- **The catalogue needs a public repository** of its own, registered by `owner/name`; a branch of a private fork
  can't be listed.
- **`build.py --check` misses relative imports** that leave the package. Before step 1 it passed while
  `admin_slides.py` still did `from . import deck_editor`. The package has none now; the check should still
  refuse them (raised in PLAN.md's questions for Stefan).
- **Line endings:** SlideMage stores text LF and checks out CRLF (`text eol=crlf` per extension); this
  repository uses the template's `* text=auto eol=lf`. Stored contents are the same, so changes copied
  between the two give no line-ending diffs.
- **GitHub access on Jürgen's Linux machine:** SSH to GitHub is refused (no key); `gh` is logged in. The local
  copy pushes over HTTPS with `credential.helper = !gh auth git-credential` set in its git config.
- **SlideMage's `.venv` lacks `segno`** (the QR-code feature's dependency), so SlideMage's own tests fail to
  start there until `pip install segno`. The plugin's tests don't need it.
- **Stefan's handover** gives `github.com/JuergenFleiss/slidemage.git` as the clone URL; the repository is
  `stpalan/SlideMage`. Its line numbers are slightly off from `develop` (for example `Deck.course_url` is at
  `deck_scan.py:102`, not 55).
